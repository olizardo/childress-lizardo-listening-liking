# Remediation Plan: Statistical Audit Findings

Addresses the 6 issues from the audit of the Bayesian crossed-random-effects
multinomial pipeline (Models 1–5, `Scripts/run_brms_*.R`,
`Scripts/generate_md_tables.R`, `overclaiming_report.qmd`).

Ordering matters: diagnostics (Phase 1) must run before anything else,
because if the saved fits show convergence problems, the WAIC comparison,
sensitivity analyses, and report language in later phases all need to be
redone against corrected fits rather than the current `rds/model_brms_*.rds`
objects.

---

## Phase 1 — Convergence diagnostics (do first, gates everything else)

**New script:** `Scripts/check_convergence.R`

- Load each of the 5 saved fits (`model_brms_intercepts`, `model_brms_slopes`,
  `model_brms_constrained_likeonly`, `model_brms_constrained_under_over`,
  `model_brms_constrained_over_true`).
- For each: extract max Rhat, min ESS bulk/tail across all parameters
  (`brms::rhat()`, `posterior::summarise_draws()`), divergent transition
  count and max treedepth hits (`brms::nuts_params()`), and save a per-model
  diagnostics row to `cache/diagnostics_summary.csv`.
- Render a compact diagnostics table to `cache/table_diagnostics.md` (model,
  max Rhat, min ESS bulk, min ESS tail, n divergences, n max-treedepth hits).
- **Decision point:** if any model shows Rhat > 1.01, ESS < 400, or a
  non-trivial divergence count, that model must be refit with a higher
  `adapt_delta` (e.g. 0.99) and/or reparameterized before Phases 2–5 use it.
  Given Models 1–2 were fit at `adapt_delta = 0.90` and Models 3–5 at 0.95,
  refit Models 1–2 at 0.95 regardless, so all 5 models are on comparable
  sampler settings before being compared in Phase 2.
- Refits (if needed) run on Hoffman2 using the existing `submit_brms_*.sh`
  templates, edited only to bump `adapt_delta`; outputs overwrite the
  existing `rds/model_brms_*.rds` files via `file_refit = "on_change"`.

**Deliverable:** `cache/table_diagnostics.md`, appended to the manuscript as
a new "Model Diagnostics" subsection under Methods (brief — one paragraph
plus the table), and a go/no-go note on whether any refits were required.

## Phase 2 — Fix the WAIC model-comparison table (paired SE)

**New script:** `Scripts/compute_loo_compare.R`

- Ensure every one of the 5 fits has a `waic` criterion attached
  (`add_criterion(fit, "waic", cores = 4)`), recomputing for
  `model_brms_intercepts` and `model_brms_slopes` if missing (currently
  only the 3 constrained models have a separately saved `waic_brms_*.rds`).
- Call `loo_compare(waic1, waic2, waic3, waic4, waic5)` to get the
  **paired** `elpd_diff` and `se_diff` for every model relative to the best
  model, not independent marginal SEs.
- Rebuild `cache/table5_fit.md` with: WAIC (SE), elpd_diff, se_diff, and a
  derived `elpd_diff / se_diff` ratio so readers can see whether each
  comparison is well outside noise (rule of thumb: |ratio| > ~2 treated as
  suggestive, not "confirmed").
- Update `Scripts/generate_md_tables.R` fit-table block to source this
  script's output instead of the hand-typed `Delta_WAIC` vector.

**Deliverable:** corrected `cache/table5_fit.md`; rewritten "Bayesian Model
Comparison" narrative in `overclaiming_report.qmd` that only claims a model
comparison is decisive when `se_diff` supports it, softening/removing
language like "captures virtually the entire remaining gain" if the paired
SE doesn't support it.

## Phase 3 — Sensitivity checks for the J = 20 genre-slope structure

**New script:** `Scripts/sensitivity_lkj_prior.R`

- Refit Model 5 (the preferred full-slopes model) twice more on Hoffman2
  with alternative `lkj()` concentration priors (e.g. `lkj(1)` — uniform —
  and `lkj(4)` — stronger shrinkage toward zero correlation) holding
  everything else fixed.
- Compare the posterior for the genre-level intercept–slope correlation
  (currently reported as $r=-0.83$) across the three prior settings and
  report how much it moves; save to `cache/sensitivity_lkj.csv` and a small
  comparison figure (posterior density overlay, 3 priors).
- Add a caveat sentence in the manuscript wherever the $-0.83$ correlation
  is discussed, noting $J=20$ clusters and reporting the sensitivity range
  rather than a single point estimate.

**Deliverable:** `cache/sensitivity_lkj.csv`, one new supplementary figure,
one caveat paragraph in Results.

## Phase 4 — Relabel and supplement the "Bayesian Wald test"

- In `Scripts/generate_md_tables.R`, rename the function/output from
  "Bayesian Wald Chi-Square" to something explicit about its asymptotic
  nature, e.g. "Asymptotic Posterior Wald-Type Statistic," and add a
  one-line code comment documenting the normality assumption.
- In `overclaiming_report.qmd`, reword the Table 1 introduction and the
  "Best Predictor Analysis" paragraph to state plainly that $p$-values here
  come from treating the posterior mean/covariance as if it were a sampling
  distribution under asymptotic normality, not from a frequentist sampling
  procedure — and flag that this hasn't been separately validated.
- **Lightweight validation, not new full models:** add a quick posterior
  normality check for each predictor block (e.g. compare posterior marginal
  histograms against a normal density, or report the multivariate
  Mahalanobis-based normality diagnostic) rather than fitting additional
  models. This keeps compute cost low.

**Deliverable:** relabeled Table 1, revised methods/results prose, one
diagnostic plot or table checking the normality assumption underlying the
test.

## Phase 5 — Measurement limitations and small-cell robustness

- Add a **Limitations** subsection to `overclaiming_report.qmd` (currently
  absent) covering: (a) `child_arts` is a single 7-point item with no
  reported reliability; (b) Winamp platform has only $N=10$ respondents
  sharing one fixed-effect dummy; (c) any other small demographic cells
  identified during Phase 1/2 reruns.
- **New script:** `Scripts/robustness_platform.R` — refit the baseline
  intercepts model (Model 1 only, not all 5) after (i) dropping Winamp
  respondents and (ii) collapsing Winamp into "Other," and compare the key
  `child_arts` coefficients across specifications. Save to
  `cache/robustness_platform.csv`.
- If the `child_arts` estimates are stable across these specifications,
  report that stability in the Limitations section; if not, flag it as an
  open issue rather than silently keeping the original specification.

**Deliverable:** Limitations section, `cache/robustness_platform.csv`, one
sentence in Results referencing the robustness check.

## Phase 6 — Posterior predictive check and prior sensitivity (baseline model)

- **New script:** `Scripts/posterior_predictive_check.R`
  - For the baseline intercepts model, draw posterior predictive replicates
    of `engagement_state` and compare observed vs. predicted state
    proportions *per genre* (20 genres × 4 states), summarizing as a
    small faceted plot (`Plots/PPC_Genre_State_Proportions.png`) rather than

  - Flag any genre where observed proportions fall outside the 95%
    posterior predictive band.
- **Prior sensitivity (lightweight):** refit Model 1 only (not all 5) with
  a wider fixed-effect prior (`normal(0, 3)` instead of `normal(0, 1.5)`)
  and confirm the headline `child_arts` coefficients don't materially shift;
  report as a one-line sensitivity check, not a full model comparison.

**Deliverable:** `Plots/PPC_Genre_State_Proportions.png`, one paragraph in
Methods/Limitations reporting the prior sensitivity result.

## Sequencing and compute budget

1. Phase 1 (diagnostics) — local, fast; refits only if needed (Hoffman2, ~1
   job per flagged model).
2. Phase 2 (WAIC fix) — local, fast, no refitting required unless Phase 1
   forces it.
3. Phases 3–6 — each requires at most 1–2 additional Hoffman2 refits of a
   single model (never all 5), keeping total new compute to roughly 4–6 jobs
   instead of re-running the full 5-model grid repeatedly.
4. After Phases 1–6, rerun `Rscript Scripts/generate_md_tables.R` to
   regenerate all cached tables, update `overclaiming_report.qmd` prose
   accordingly, re-render the report, and run
   `Rscript Scripts/sync_manuscript.R` to push the corrected tables/figures/
   text back to the live Google Doc.

## Out of scope (flag but don't fix now)

- Full re-specification of the Wald test as a proper Bayesian model-selection
  procedure (e.g., leave-one-covariate-out ELPD) — noted as a possible
  future improvement in Limitations, not implemented here, to keep this
  remediation pass bounded.
